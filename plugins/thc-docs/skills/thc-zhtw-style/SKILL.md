# THC zh-TW Style: 繁中技術文件風格規範

本技能定義台灣繁體中文技術文件的風格規範，管轄字元、標點、用語與術語；章節結構與寫作文法由 `thc-techdoc` 定義。
規則之間若有衝突，優先順序由高至低依序為【三】、【四】、【二】、【一】。

## 使用流程

1. 讀取 `references/punctuation.md` (【四】標點符號全文)。撰寫或修改任何中文內容前必須讀取，標點是最常出錯的部分。
2. 依本文【一】至【六】撰寫或修改內容。
3. 對產出的 Markdown 檔執行檢查腳本，腳本位於本技能 base directory (載入技能時顯示) 下：

   ```bash
   python3 "<本技能 base directory>/scripts/check_zhtw.py" <檔案.md>
   ```

   - `E` 為錯誤，必須全部修正後重跑，直到結束代碼為 0。
   - `W` 為警告 (疑似大陸用語、括號間距等)，逐項人工判斷；確認無誤者可保留。
   - 腳本只檢查機械性規則，會略過程式碼區塊、行內 code span 與 URL。YAML front matter 照常檢查，並要求寫成單行，因為多行區塊會在換行處產生空格。
4. 依【七】逐項自我檢查。術語譯法、首次夾注、語氣等語意規則腳本無法判斷，必須人工確認。

**校稿模式**：修改既有文字時適用。

- 只改不符規範之處，不改寫原意與段落結構。
- 程式碼區塊與識別字依【三】逐字保留。
- 完成後附「修改摘要」表，欄位為位置、原文、修改後、依據規則；同類修改可合併為一列。

## 【一、語言與在地用字】

1. 一律使用台灣繁體中文 (zh-TW) 與台灣資訊產業慣用語，禁止使用中國大陸用語。
2. 不內建完整詞彙表。判斷原則：以國家教育研究院樂詞網、Microsoft 繁體中文 (台灣) 術語庫、台灣資安媒體 (如 iThome) 的慣用譯法為準。若你具備網路搜尋能力且對某詞的台灣譯法沒有把握，應先查證再使用；若無法查證，保留英文原文並附上暫譯，標註【暫譯】供審稿者確認。
3. 常見中國大陸用語警示 (示例，非窮舉): 軟件、網絡、程序 (指 program 時)、數據、內存、默認、服務器、字符、接口、算法、優化、散列、補丁、零日、運維、視頻、信息 (指 information 時)、質量 (指 quality 時)、支持 (指 support 時)。遇到語感類似的詞，一律往台灣慣用方向修正 (如：維運、最佳化、雜湊、修補程式、零時差)。

## 【二、官方功能術語：保留英文原詞】

1. 凡屬特定產品、框架、標準的「功能專名」，即會出現在官方文件、設定檔鍵名、API 路徑或錯誤訊息中的詞，一律保留英文原詞，不翻譯。例：guardrail、Virtual Key、recognizer、trace、span、worker、callback、inference profile、fail-closed、`pre_call`、health check。
2. 判斷測試：讀者拿這個詞去搜尋官方文件或錯誤訊息時，是否需要它的英文原形? 需要，則保留英文；不需要 (屬通用 IT 概念)，則使用台灣慣用中文譯名。通用詞示例：server 譯「伺服器」、image 譯「映像檔」、package repository 譯「套件庫」、code repository 譯「儲存庫」、gateway 譯「閘道」、token (泛指存取權杖時) 譯「權杖」、log 譯「日誌」。同一英文詞若有多個語境譯名 (如 repository)，依語境選定後全文一致。
3. 夾注方向：全文「首次出現」時加半形括號夾注，方向固定為「後文採用的詞在前、輔助說明在後」：
   - 保留英文的功能專名，英文在前。例：guardrail (防護規則)，之後全文僅寫 guardrail。
   - 採用中文譯名的通用詞，中文在前。例：閘道 (gateway)，之後全文僅寫閘道。
   - 同一詞不重複夾注。
4. 夾注內容的穩定性：夾注中的中文說明必須採用業界通行譯法，已有通行譯法的詞不得自創新譯。例：placeholder 的夾注必須寫「預留位置」(Microsoft 繁體中文術語庫譯法)，不可寫「遮罩代替標記」等自創說明。判斷來源同【一】第 2 條；無通行譯法且沒有把握時，給出最貼近的暫譯並標註【暫譯】。同一詞在同一份文件與後續文件中，夾注說明必須一致。
5. 夾注位置限制：
   - 夾注不得置於另一組括號內部 (禁止巢狀括號)。若術語首次出現於某組括號內，該處不夾注，延後至該詞下一次獨立出現處再夾注。反例 (禁止): `postgres (health check (健康檢查) 通過)`。
   - 「首次出現」以正文的閱讀順序計，表格儲存格中的出現也算首次；程式碼區塊內的出現不算。

## 【三、程式碼識別字保護 (硬性規則，優先於其他所有規則)】

1. 參數名、設定鍵名、環境變數、指令、旗標、檔名、路徑、URL、埠號、版本字串、模型字串、API 路徑等技術識別字，一律「逐字保留」：
   - 禁止插入或替換任何全形字元 (含全形斜線 `／`、全形括號、全形空格)。
   - 禁止增刪空格、改變大小寫、拆開或合併。
   - 例：`input/output_cost_per_token` 中的 `/` 必須維持半形。
2. 上述識別字無論出現在內文、表格儲存格或標題，一律以反引號 `code` 標記。
3. 程式碼區塊、指令範例、設定檔內容、架構圖 (以程式碼區塊呈現者): 除非使用者明確要求，否則一個字元都不可更動，包含其中的註解文字也不做風格潤飾。

## 【四、標點符號：字元級對照表】

全文見 `references/punctuation.md`，撰寫前必須讀取。要點：中文句讀用全形，`?` `!` 與夾注括號用半形，冒號依前一字元是否為中文字決定全形或半形，禁用 Unicode 箭頭、破折號、刪節號等特殊符號，【】僅限白名單標籤。

## 【五、數字格式】

1. 版本號、埠號、數量、百分比、日期、時間、代碼、編號一律用半形阿拉伯數字。
2. 日期寫作「2026 年 3 月」或 ISO 格式 2026-03-15，同一份文件擇一並保持一致。
3. 成語與慣用語保留中文數字 (如「一律」「三三兩兩」)。

## 【六、語氣與句長：依區塊分流】

1. 正文段落：精簡、直述、講重點。短句優先，一句一概念；可用「您」但不堆疊敬語，不使用情緒化或行銷式修辭。
2. 表格儲存格、速查區塊、清單項目、圖說：允許短語體，省略主詞與句尾助詞。
3. 警告與注意事項：直接陳述風險與後果，不誇大。例：【重要】設定後不可更改，否則已儲存憑證將無法解密。

## 【七、輸出前自我檢查】

產出後逐項檢查並修正。標註「腳本」者可由 `check_zhtw.py` 協助偵測，其餘必須人工確認。

- (a) 技術識別字中是否被插入全形字元或空格? (最高優先) 識別字是否都加了反引號?
- (b) 中文行文中是否出現半形逗號、句號、頓號或分號? (尤其在半形括號、引號旁) (腳本)
- (c) 問號與驚嘆號是否為半形? 後接中文時是否加了空格? 後接右括號或引號時是否誤加了空格? (腳本)
- (d) 冒號是否依「前一字元是否為中文字」正確選用全形或半形? 半形冒號後是否加了空格? (腳本)
- (e) 是否殘留禁用符號? (含 `≥`、`→`、`✓`、`…`、`——`、`～`、全形運算符、圈號、裝飾符號) (腳本)
- (f) 非架構圖區塊是否出現框線字元或 ASCII 圖形排版? (腳本僅偵測框線字元)
- (g) 是否有中國大陸用語? (腳本僅偵測常見詞)
- (h) 官方功能術語是否誤譯? 首次夾注方向是否正確? 通用詞是否誤留英文?
- (i) 夾注說明是否採用通行譯法且全文一致? 是否出現巢狀括號? (腳本僅偵測巢狀括號)
- (j) 標籤 `【】` 是否只使用白名單內的詞? 位置與密度是否正確? 標題已表達的語意是否被逐項重複? (腳本僅偵測白名單)
- (k) 中英文之間是否漏加空格? 括號外側間距是否正確? 數字與範圍寫法是否一致? (腳本)
- (l) 表格與速查區是否維持精簡短語體?
