# THC Techdoc: 技術文件結構規範

本技能把素材整理成一份結構化技術文件，定義章節結構與寫作文法；字元、標點、用語與術語由 `thc-zhtw-style` 定義。
程式碼識別字保護規則 (`thc-zhtw-style` 的【三】) 優先於一切。

## 開始前

1. 載入 `thc-zhtw-style` 技能並讀取其 `references/punctuation.md`。無法載入時停下告知使用者，不得在缺少風格規範的情況下產出。
2. 讀取本技能的 `references/layers.md` (分層定義、主體文法、寫作文法 G1 至 G7、標籤、載體規範)。階段二撰寫前必須讀取。
3. 確認素材來源：對話內容、使用者指定的檔案、`HANDOFF.md`、指令輸出等。素材不明時先詢問。

## 規範用語

本技能使用三級規範用語：

| 用語 | 意義 |
| --- | --- |
| 必須 | 無條件要求，不得偏離 |
| 應該 | 強烈建議，偏離時必須就地標註例外並說明原因 |
| 可以 | 可選，依情況採用，無須說明 |

## 階段一：判定 (人工確認點)

閱讀素材後必須先輸出判定結果，然後停下等使用者確認。

1. 文件型態：建置部署遷移、規範標準字典、維運 SOP 與排錯、設計說明與選型、事後檢討報告、教學概念說明 (名稱與 `references/layers.md` 的啟用表一致)。
2. 主體型態：程序型、定義型、論述型。混合則指出主導型態。
3. 三個維度的取值：
   - 實體：素材中要逐一列舉的對象。
   - 推進單位：主體如何分段。
   - 驗收單位：判定成功的最小可觀測事實。
4. 篇幅檔次：依下表判定，任一欄達到某檔即取該檔，取最高檔。

   | 判準 | 輕量 | 標準 | 完整 |
   | --- | --- | --- | --- |
   | 實體數量 | 1 | 2 至 5 | 6 以上 |
   | 含不可逆操作 | 無 | 有 | 有 |
   | 讀者含未來接手者 | 否 | 是 | 是 |
   | 跨團隊交付 | 否 | 否 | 是 |

5. 資訊缺口清單：素材不足以填滿的部分逐項列出並提問。不得憑推測補寫。
6. 輸出設定：輸出檔案路徑，以及中繼資料 (metadata) sidecar 檔的檔名與格式。使用者未指定時提出建議值並請使用者確認。

判定為輕量檔且素材無缺口時，可以直接進入階段二，但仍必須在文首列出判定結果。

## 階段二：產出

依 `references/layers.md` 撰寫。要點：

- 不變核心四層必須具備：L1 識別層、L2 決策層、L4 主體層、L7 誠實層。
- 條件層 L3 全景層、L5 驗證層、L6 持續層、L8 索引層依文件型態的啟用表決定。
- 輸出順序固定為 L1、L2、L3、L4、L5、L6、L7、L8。決策層必須在主體層之前，不得調換。
- 主體層依判定的主體型態選用文法，全文必須一致不混用。
- 寫作文法 G1 至 G7 強度為「應該」，偏離時必須以例外定式就地標註並寫明原因。
- 行內標籤只可使用封閉標籤集；憑證、金鑰、密碼絕不入文。

輸出 Markdown 單一檔案，另附中繼資料 sidecar 檔。

## 階段三：輸出前自我檢查

1. 對輸出檔執行 `thc-zhtw-style` 的檢查腳本，`E` 必須全部修正至結束代碼為 0。腳本位於本技能 base directory 的同層技能目錄：

   ```bash
   python3 "<本技能 base directory>/../thc-zhtw-style/scripts/check_zhtw.py" <輸出檔.md>
   ```

2. 逐項確認下列清單，未通過先修正，並在文末回報檢查結果。

- [ ] 四層不變核心齊備，且決策層在主體層之前
- [ ] 每個決策都有原因，且原因非同義反覆
- [ ] 每個已知問題都有原因，且指向可推理的機制
- [ ] 每個操作、條目或主張都符合對應型態的必備要件
- [ ] 每個區塊都標明適用對象
- [ ] 主體型態全文一致，未混用
- [ ] 所有文法偏離都已標註例外並寫明原因
- [ ] 標記僅來自封閉標籤集，未使用圖形符號，語義一致
- [ ] 規範強度用三級動詞表達，未與【必要】標籤混用
- [ ] 每節都有自我完備摘要句，且無跨節指涉
- [ ] 未使用 YAML front matter
- [ ] 已知問題表非空。若確無問題，明文寫出本次未遇到問題，而非省略該節
- [ ] 推測內容與已驗證內容已區分標示
- [ ] 無真實憑證明文
- [ ] 風格規範自我檢查 (a) 至 (l) 全部通過，檢查腳本結束代碼為 0

## 重要規則

- 階段一完成後必須停下等使用者確認，輕量檔且無缺口者除外。
- 素材不足時提問，不憑推測補寫。
- 素材中的失敗嘗試與錯誤訊息必須轉入已知問題表，不得當雜訊刪除。
- 素材出現真實憑證或機密時必須以預留位置替代，僅在 L8 索引層記錄取得途徑。
- 不自行 commit 產出的文件；是否納入版本控制由使用者決定。
